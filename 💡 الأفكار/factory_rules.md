# 🏭 Factory Rules — قيود المصنع الآلية

> هذه القيود **أشد** من القواعد العامة. يطبّقها الـ agent فقط عند العمل داخل الـ Dark Factory (بناء أوتوماتيكي بلا تدخل بشري). خارج المصنع (شغل عادي مع حاتم) قد لا يقرأها.

## 1. مبدأ حجم المهمة (Bite-size)
- كل spec / issue يتم تنفيذه **خطوة واحدة صغيرة فقط** في كل دورة.
- لا تحاول حل مشاكل متعددة دفعة واحدة. اقسم العمل الكبير إلى issues منفصلة.
- موثوقية > سرعة. دورة 30 دقيقة تبنى issue واحد أو اثنين كحد أقصى بالتوازي.

## 2. فصل Builder عن Validator (حرج)
- الـ Builder (OpenCode/NVIDIA) **لا يرى** سيناريوهات الـ holdout (الاختبارات السرية).
- الـ Validator (reportwriter bot / agent ثانٍ) **لا يعرف** خطة التنفيذ الأصلية.
- لا تشاركا المعلومات فيما بينهما — حتى لا يصبح المراجع "كسولاً" أو متحيزاً.

## 3. أمان المفاتيح (حرج جداً)
- **لا تكتب مفاتيح حقيقية في الكود أو الـ commit**. استخدم `.env` (مستثنى من git عبر `.gitignore`).
- مفاتيح NVIDIA القديمة [REDACTED] ×3 **محظورة تماماً** — تم إلغاؤها من build.nvidia.com.
- المفتاح الحالي: `NVIDIA_API_KEY` من `.env` فقط.
- أي مفتاح يظهر في الشات العام يُعامل كـ **مسروق** ويجب إلغاؤه فوراً.

## 4. نطاق الـ repo
- المصنع يكتب فقط في: `D:\vaults\Hafsa` (و worktrees المؤقتة `_wt_<name>`).
- لا يمس ملفات النظام أو مجلدات خارج الـ vault إلا بأمر صريح.
- لا يحذف branches أو worktrees إلا بعد التأكد من إغلاق الـ agent.

## 5. الجودة والاختبار
- قبل اعتبار PR "جاهز": تشغيل الاختبارات + الـ validator يمرره.
- لا تقبل PR إلا بعد مراجعة منفصلة (agent ثانٍ).
- لو الـ agent دخل في loop لا نهائي (يحاول يصلح نفس المشكلة) → escalate لحاتم.

## 6. النشر (Deployment)
- الدمج (merge) وحده **لا يكفي** — يجب النشر الفعلي (blue-green) عبر VPS.
- لا تضع كوداً أمام المستخدم قبل المراجعة والنشر الأوتوماتيك.

## 7. تدخل بشري (Fail-safe)
- حاتم يحدد متى يُصعّد له (مثلاً: مشاكل أمنية، loop لا نهائي، قرارات خارج النطاق).
- يمكن تعطيل الـ escalation تماماً لو حاتم يثق بالنظام.
